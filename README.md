# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

## 可回放随机与飞行检查（核心）

- **分配方案可回放**：随机种子、区组长度、分层因素（研究中心 × 年龄段）固化为版本化的 `AllocationScheme`；序列由 FNV-1a 派生种子 + mulberry32 + 区组内确定性 Fisher–Yates 洗牌生成，同一份方案在任意时间、任意机器重建结果逐比特一致（`utils/randomization.ts`）。
- **逐例对账**：飞行检查按每条已发号码当时的方案版本重建整段序列，逐例核对随机号与组别，报告跨层**第一个对不上的位置**（含受试者、实发值、重建期望值、不符类型）。
- **同分层名额并发单放**：在线发号分“占用名额 → 确认发号/取消”两阶段，名额锁持续整个事务；两名协调员同时争用同一分层名额时只放行一条，另一条被驳回并记审计；不同分层互不阻塞；驳回方可重试拿下一名额。
- **断网纸卡并入**：纸卡按现行方案预生成（随机号/组别与线上同源）；断网期间开批次凭卡发号；网络恢复后按方案逐例重建并入。位置错位、随机号不符、重号等**硬错误整批失败、台账不动、批次保留可重试**；仅组别冲突时按重建版入账并保留纸卡版，生成两版裁决案交监查员。
- **种子换版只向后生效**：新种子/新区组长度生成新方案版本，之后入组挂新版本；已发号码永久携带发出时的版本号并按原序列核验。监查员裁决采用纸卡版后，对账承认裁决（随机号仍须一致）。
- **审计仅追加**：占用驳回、纸卡印制/发号、并入成败、裁决、换版、对账结果、紧急揭盲全部入流水。

## 可用流程

- 入组：机构、分层因素和受试者编号校验后占名额并按方案回放生成分层区组随机号与治疗组。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组（在线与离线批次同规则）。
- 角色隔离：研究者、药品管理员和监察员看到不同的分组隐藏规则；冲突待裁决条目对所有角色显式标红。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写。
- 离线队列：印制备用纸卡 → 断网批次发号 → 联网后重建核对并入，冲突交监查员裁决，失败保留现场可重试。
